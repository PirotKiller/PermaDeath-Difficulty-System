# PermaDeath Relic Resource Pack

Custom inventory art for all 23 relics. Each relic is a recolour of the genuine vanilla
1.19.2 sprite for its base item, so it keeps that item's silhouette and shading — Dragon
Slayer looks like a sword, Hermes Boots look like boots — just in the relic's colours.

Generated by `tools/generate_resourcepack.py`. Don't hand-edit the JSON; edit the manifest
in that script and re-run it, or your changes will be overwritten on the next regeneration.

## How it works

Each relic carries a `CustomModelData` value (see `relics.custom-model-data` in `config.yml`,
defaults in `RelicManager.java`). The pack rewrites the vanilla model for each base item to add
`overrides` that swap in a custom model when that value is present.

Numbering is by tier: `1xxx` tier 1, `2xxx` tier 2, `3xxx` tier 3.

> `CustomModelData` is **cosmetic only**. Relic identity is the persistent-data tag, and the
> plugin never reads model data to decide what an item is — a player can put any
> `CustomModelData` on any item, so trusting it would reintroduce the rename exploit.

### Why the generator needs the client jar

The base models we rewrite (`diamond_sword.json`, `elytra.json`, `shield.json`, …) ship to
every player and apply to *ordinary* items too, not just relics. If one of them differs from
vanilla in any way other than our appended `overrides`, we change how normal swords and elytra
look for everyone. So the generator reads each vanilla model straight out of the official
1.19.2 client jar and appends to it, rather than reconstructing it by hand.

The jar is downloaded on first run into `.cache/` (gitignored) and SHA-1 verified against
Mojang's published manifest. It is never redistributed as part of the pack.

### Override ordering

Minecraft applies the **last** override whose predicates all match. Vanilla's own
`crossbow.json` depends on this, so it's a safe rule to build on. The generator emits our
`custom_model_data` overrides first and vanilla's state overrides (`broken`, `blocking`)
after, so vanilla states keep winning:

- A broken Infernal Elytra shows the broken sprite, not the intact custom one — the player
  needs to see the damage state.
- Shields get a third group (`blocking` + `custom_model_data`) after vanilla's `blocking`
  rule, so a raised relic shield stays custom instead of reverting to a plain shield.

## Using it

1. Zip the **contents** of this directory (so `pack.mcmeta` is at the zip root, not inside a
   folder). `tools/build_resourcepack_zip.py` does this and prints the hash.
2. Host the zip at a direct download URL.
3. In `server.properties`:
   ```properties
   resource-pack=https://your-host/pdds-relics.zip
   resource-pack-sha1=<sha1 of the zip>
   require-resource-pack=true
   ```
   The SHA-1 must match or clients re-download every join.

## Replacing the art

Drop 16x16 PNGs over the files in `assets/pdds/textures/item/`, keeping the filenames.
Nothing else needs to change — the models and overrides already point at them.

For a 3D model instead of a flat sprite, replace `assets/pdds/models/item/<relic-id>.json`;
the override already references it.

To change a relic's colour scheme instead, edit its `ramp` in the generator's `RELICS` table
(five hex stops, darkest to lightest) and re-run. The ramp is applied by pixel luminance, so
the vanilla shading carries through automatically.

## Known limitations

### Worn armor still looks vanilla

`CustomModelData` changes how an item looks **in the inventory and in the hand**. It does not
change the armor texture rendered on the player model. Helmet of Hades looks custom in your
inventory but renders as a normal netherite helmet when worn.

Fixing that needs a different technique — armor trims (1.20+, not available on 1.19.2), or
the leather-armor colour/overlay trick, which only works for leather base items. The relics
use netherite/diamond/turtle bases, so worn appearance stays vanilla unless you rebase them
onto dyed leather.

### Tridents render vanilla while held

1.19.2 draws a held trident with a separate hardcoded model (`item/trident_in_hand`,
`builtin/entity`) that ignores `CustomModelData`. Propulsion Trident and Poseidon's Trident
therefore show their custom art in the inventory, on the ground and in item frames, but look
like an ordinary trident in hand and when thrown.

### Shields are a flat sprite, not a 3D shield

Vanilla's shield model is `builtin/entity` — the shape comes from a hardcoded entity renderer
that only knows about banner patterns, so there is no vanilla shield sprite to recolour.
The pack draws one and uses a flat `item/generated` model for the two shield relics.

Each shield relic ships two models — the normal held pose and a `-blocking` variant that
copies vanilla `shield_blocking.json`'s raised-to-face transforms, so right-click *visibly*
raises the sprite. Without that second model the flat sprite would stay at the player's
side while the shield was actually blocking server-side, which reads as "right-click does
nothing."

Net effect: a clean upright icon in the inventory, correct pose held and raised, but a flat
plate rather than a 3D shield while held. Replacing `assets/pdds/models/item/ultra-shield.json`
(and its `-blocking` variant) with real 3D models is a drop-in change if you want the depth.

### Lucky Clover is colour-limited

Its base item is `fern`, and the client multiplies fern's inventory sprite by a hardcoded
grass tint (`124, 189, 107`). The generator pre-divides by that tint so the intended colour
comes out right, but bright warm tones can't survive the red channel being scaled to 48%.
The generator reports how many channels clipped. Practically this means the clover reads
green, which is what it should be anyway.
